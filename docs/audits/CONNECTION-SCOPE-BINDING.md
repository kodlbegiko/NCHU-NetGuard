# Connection-scoped local quota selection

Status: candidate. Previously the Swift runtime automatically labeled campus-address Ethernet as a particular dorm, despite the CLI refusing this inference. The IP prefix now supplies only a descriptive candidate hint, not a quota classification. User chooses a local observation scope from the current network menu. The choice is in-memory, bound to a recent interface, interface index, address-set identity and route event token. Route events, system sleep, changed default interface/address or invalid/missing interface samples revoke the binding; no persistent identity or automatic reclassification. The next interval across a scope transition is unattributed. Existing history is preserved; no migration retroactively reassigns old inferred data. The tradeoff is one explicit selection after a new connection or wake, and unclassified secondary interfaces until a reviewed multi-binding UI is available. This is intentionally conservative and is not verification of provider billing. No network settings are changed. Tests cover invalid, changed and stale bindings. Exact macOS CI and real device usability still required.
