# History file write safety

The process/agent, connection and traffic-event stores now capture exact bounded bytes under the existing directory lock, validate the decoded records, and use private descriptor-relative compare-and-replace with file fsync and directory fsync. Process record deletion compares the exact bytes under the same cooperating lock. This closes the read/encode/replace gap for cooperating writers and rejects symlinks, hardlinks and foreign owner files. It is not a guarantee against arbitrary same-user non-cooperating renames or multi-store atomicity. All stores preserve malformed input on update; explicit history deletion is still user-driven. Added hardlink and permission regressions; exact macOS CI remains necessary.

- R4-DATA/SECURITY: history bundle create/recover-copy now writes private exclusive files and fsyncs each staged payload and directory before same-parent descriptor-relative `renameatx_np(RENAME_EXCL)`; destination conflict enforced atomically, even a dangling symlink or last-moment directory creation. If parent fsync fails after publication, preserve the complete copy and report uncertain durability. Added deterministic pre-publish failure and destination-race tests; source remains intact; no active-store overwrite or live multi-store restore is authorized. Same-user noncooperating ancestor races are not fully excluded. Prior exact code CI #217 [success](https://github.com/kodlbegiko/NCHU-NetGuard/actions/runs/45837750342); new macOS CI required.
